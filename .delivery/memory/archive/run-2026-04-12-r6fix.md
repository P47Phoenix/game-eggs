## What Went Well

### 1. Scope contradiction caught and self-corrected at Stage 1 DoD (1 iteration)
The Architect correctly identified that the idea brief listed the startup crash fix as an egg-JSON deliverable while simultaneously acknowledging the root cause was an image-layer defect (`/rvs` VOLUME + hardcoded path, no env-var override). The contradiction was flagged and resolved in a single self-correction iteration before Stage 2 began. This prevented wasted implementation effort on a change that could not work.

### 2. Gate 1 investigation used the correct source of truth
When resolving Gate 1 (does the image expose a path-override env var?), the team correctly went to the public repo source (`https://github.com/danpowell88/ravenshield_dedicatedserver`) to inspect the entrypoint and Dockerfile directly. The conclusion — no override variable exists, therefore the crash-fix track is removed from scope — was reached from first-principles source review, not assumption.

### 3. Docker VOLUME semantics correctly identified
The team correctly reasoned that a `FROM upstream + RUN chown` custom image approach would be technically broken: any `chown` applied after an inherited `VOLUME` declaration is discarded at container runtime because Docker initialises the anonymous volume from the image layer at mount time, not from subsequent RUN-layer mutations. This prevented a false solution from entering the implementation track.

### 4. Stage 6 DoD: QA caught 2 blocking issues and self-corrected in 1 iteration
QA identified two blocking issues during Stage 6 review: incorrect variable description ordering in the egg JSON, and a missing invalid-value warning that should have been surfaced to the operator. Both were resolved in a single self-correction round. This is the expected behaviour — catches at DoD gates, resolved before UAT.

### 5. Track A delivered cleanly
The unconditional Track A deliverables (inline map/gametype descriptions, normalised `max:128` constraints, expanded 6-slot rotation) were completed without rework on the implementation track, and UAT completed in a single round with zero self-corrections at Stage 7.

## What Did Not Go Well

### 1. Orchestrator violated the Prime Directive twice (domain research performed directly)
The orchestrator performed domain research directly on two occasions — fetching Dockerfiles and running Docker tests — rather than delegating these tasks to the Architect agent. This violates the Prime Directive: the orchestrator coordinates and gates; it does not perform specialist domain work. The downstream impact was limited because the findings were technically correct, but the process violation creates a pattern risk where the orchestrator gradually absorbs domain work and the specialist agents become underutilised.

**Root cause:** The orchestrator likely interpreted "Gate 1 must be resolved before Stage 2" as license to resolve it directly rather than tasking the Architect. The brief itself listed Docker as "available locally for further testing," which may have anchored the orchestrator to act rather than delegate.

### 2. Pipeline run ID mismatch between idea brief and execution
The idea brief records the pipeline run as `run-2026-04-11-r6fix` (dated 2026-04-11), but the actual execution run is `run-2026-04-12-r6fix` (dated 2026-04-12). This is a minor traceability defect — the brief was authored on one date and the run started the next day, but the run ID in the brief was not updated at run-start. Retrospective and artifact cross-referencing had to reconcile this manually.

### 3. Empirical Docker crash test remained pending at UAT close
The Stage 7 UAT summary records an open empirical action: `docker run --user 1000:1000` crash test (expected: still fails — confirms B2 track; unblocks PR). This test was listed as pending rather than completed. Because the B2 track had already been scoped out based on source review, the omission did not block delivery, but it means the Gate 2 pre-merge check (archive.org URL live + crash test confirmation) is still outstanding at retrospective time. A PR should not merge until this is cleared.
